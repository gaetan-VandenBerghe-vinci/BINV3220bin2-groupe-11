EF-32 et EF-33 : exigences face aux tests

Cette matrice relie les cas précis du cahier des charges aux tests existants et à leurs assertions. Un test ne compte comme couverture que si ses assertions vérifient réellement le résultat attendu; le nom du test, à lui seul, ne suffit pas.

EF-32 · Candidater et retirer Les refus de candidature, contrôles de rôle, limites du message et retraits sont testés par l’API.
EF-33 · Voir ses candidatures et statuts L’isolation et le statut « En cours » sont testés; les statuts traités et retirés restent à couvrir.
Exécution ciblée 24 tests API et 7 tests d’interface exécutés; tous réussis.

Exigences du cahier des charges

Les formulations de référence viennent de la section 7.4 du cahier des charges. EF-32 porte sur une candidature à une offre publiée, le message facultatif et le retrait avant traitement. EF-33 demande de consulter ses candidatures et les statuts « En cours », « Retenue », « Non retenue » et « Retirée ». Ouvrir docs/cdc_gesta_developpement.md.

Partiel Seul « En cours » est testé par l’API; les statuts traités, leur affichage et « Retirée » restent non couverts.

Écart fonctionnel à garder visible

EF-33 demande le statut « Retirée ». Or le retrait supprime la ligne de candidature : offers.repository.ts exécute un DELETE et API.md précise que l’enregistrement est supprimé. Le type API ne prévoit pas WITHDRAWN. Le retrait est donc testé comme action EF-32, mais son historique ne peut pas être consulté comme statut EF-33.

Le choix de suppression définitive est également noté dans docs/semaine-2/bilan.md. Cette matrice rapporte cet écart sans supposer que la décision d’implémentation satisfait l’exigence.

Exécution pendant cette séance

Les suites ciblées ont été lancées avec les commandes npm run test -w backend -- tests/offers.test.ts et npm run test -w frontend -- tests/OffersPage.test.tsx. Résultat : le fichier backend passe avec 24 tests sur 24; le fichier frontend passe avec 7 tests sur 7. Cette réussite confirme que les tests existants passent, pas que tous les cas d’EF-32 et EF-33 sont couverts.

Sources principales : cahier des charges, § 7.4, tests API, tests frontend et contrat API.
